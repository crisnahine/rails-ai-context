Your coding agent guesses your Rails app. Let it ask.

rails-ai-context turns your Rails app into the source of truth for Claude Code, Cursor, GitHub Copilot, OpenCode and Codex CLI: {{tools}} read-only tools answer from the schema, the models, the routes, the controllers and the views, over MCP or in any terminal.

Every answer is read from the app, says how sure it is, and still comes when the app cannot boot.

Install in one paste See what it answers 
$ bundle add rails-ai-context --group development
$ bin/rails generate rails_ai_context:install --tools claude --defaults

The problem

The facts are in your app. The assistant writes from memory.

An assistant writing Rails code knows what an average Rails app looks like. Yours has its own columns, associations, filters and test setup, and it starts every session with none of that. You catch the guess, fix it, re-prompt, and something next to it breaks.

What it answers

The assistant asks. The app answers.

Each answer below was recorded while this page was built, by running the gem at {{commitShort}} against the sample app in this repository: a blog with Devise, an admin namespace, a JSON API, a Sidekiq job and a FactoryBot suite. It was read without booting, which is the tier an app with a missing credential or a broken initializer gets.

It meets the app: a walkthrough in one call

The stack, the gems that matter, the models and how they connect, the routed controllers, the jobs, the mailers, the frontend and how tests are set up. The context files the install writes carry a compact version of this, so the first turn of a session starts here.

It asks about a table

Columns with their types, nullability and defaults, the indexes, and which model sits on the table. With the app booted the answer comes from the database connection; without it, from db/schema.rb, db/structure.sql or the migrations.

Before it calls an association

The model is read with the Prism parser: associations with their options, validations including the implicit ones, enums, scopes with their bodies, callbacks in order, the concerns it includes and the methods they bring. A scope with a literal body is [VERIFIED], one built at runtime is [INFERRED], and in this tier every record is capped at [STATIC].

Before it writes an action

The actions, every filter that applies with where it was inherited from, the strong parameters, the layout, and schema hints for the models the controller touches. The admin controller below gets authenticate_user! from ApplicationController and require_admin from its own base class.

Before it writes a test

The framework, where the factories or fixtures live, the traits they define, and a template in the app's own style, so a new test matches the suite instead of the assistant's habits.

It traces a method

search_code with match_type: trace returns the definition and its source, what it calls, its siblings, every caller grouped by file and labelled by kind, and the tests that reference it. One call in place of a file-by-file search.

It reads the routes

Verbs, paths, actions and route helpers, grouped by controller with the filters that apply to each. Read from config/routes.rb here, so the answer says what it cannot count without booting: the routes engines and gems draw, and the devise_for line it did not expand.

Every answer ends the same way. A tier line names where the facts came from, sections that need a booted app say [UNAVAILABLE] and why, and most answers name the next call in a hint. The last line asks the assistant to offer you an issue when rails-ai-context itself answered wrong.

{{tools}} tools

Read-only, and all of them answer from your app

Over MCP each name carries a rails_ prefix, as in rails_get_schema. From the command line the short name works: rails-ai-context tool schema --table users. About half take detail=summary|standard|full.

{{toolList}}

The list, the names and the one-line summaries are read from the tool registry when this page is built, and the categories from the tools reference, which has every parameter. MCP clients can also read five resource templates and nine static resources, such as rails-ai-context://models/{name} and rails://schema.

How it works

Read once, tagged, handed over

{{introspectors}} introspectors read the app, one per kind of fact. {{tools}} tools compose their answers. The install writes the files each AI tool reads, so the assistant knows the tools exist and how to ask.

What a tool call does

  1. The call arrives over MCP from the AI tool, or from rails-ai-context tool NAME in a terminal, or from bin/rails 'ai:tool[NAME]'.
  2. The registry resolves it. Every tool is auto-registered when its class loads, and the CLI accepts schema, get_schema and rails_get_schema alike.
  3. The introspectors read the app. With the app booted: live reflection, the database connection and the routes Rails drew. Without it: config/routes.rb, the schema dump and the source files, with the answer saying so.
  4. Prism parses each file once into a cache keyed by the file's content, and a single walk feeds every listener: associations, validations, scopes, callbacks, strong parameters.
  5. Each record is tagged by how it was read, and the introspection is cached with a fingerprint of the app, so an edit to a model is seen on the next call.
  6. The answer is composed: schema hints for the models it touches, a cut at the response budget, a tier line and, for most tools, a next-call hint.

What the install writes

  1. The MCP config each chosen tool reads: .mcp.json, .cursor/mcp.json, .vscode/mcp.json, opencode.json or .codex/config.toml, merged into one that exists.
  2. One root context file. AGENTS.md carries the project overview and the tools guide when Cursor, OpenCode or Codex is chosen, and CLAUDE.md imports it; otherwise CLAUDE.md carries it. Copilot gets its own copy.
  3. Rules that load where they apply: the schema when a migration is open, the models under app/models, the controllers under app/controllers, in each tool's own format.
  4. Six anti-hallucination rules in the root file: verify before you write, mark every assumption, query even when it feels standard, check the inheritance chain, treat empty output as a signal, re-query after writes.
  5. Its own configuration: an initializer and .rails-ai-context.yml in a Gemfile install, the YAML file alone standalone, and two .gitignore lines.
  6. Nothing you wrote. Your lines around its markers stay, and uninstall takes back only what it wrote.

bundle add
bundle add rails-ai-context --group development, then bin/rails generate rails_ai_context:install --tools claude --defaults. The generator asks which AI tools you use and what to write; the flags answer for it.
gem install
gem install rails-ai-context, then rails-ai-context init --tools claude --defaults in the app. The Gemfile stays as it is.
claude plugin
gem install rails-ai-context, then claude plugin install rails-ai-context --marketplace crisnahine/rails-ai-context --scope project in the app's folder. It adds the MCP server to Claude Code, gives each session the six rules, writes no context files, and runs the installed gem.
--tools
claude, cursor, copilot, opencode, codex or all. Add --cli for context files only, or --mcp-only for the MCP config only.

What it needs

  • Ruby 3.1 or newer and Rails 7.0 to 8.1. CI runs the suite on 17 Ruby and Rails pairs on Linux, plus macOS and Windows legs.
  • Optional: brakeman for security_scan, listen for watch, ripgrep for a faster search_code.
  • A booted app for query, runtime_info and doctor. Everything else also answers from the source.

Three ways in

  • MCP over stdio, the default: each AI tool's config starts bundle exec rails-ai-context serve, or rails-ai-context serve standalone.
  • MCP over HTTP, mounted inside the app at /mcp where it inherits your routing and auth, and refused outside development and test unless you turn it on.
  • The command line, with no server at all: rails-ai-context tool NAME in any terminal, or the same tools as rake tasks.
Every other setup has a prompt

No Gemfile change, CLI only, MCP only, a whole team, a folder of apps, nothing committed, MCP over HTTP, Ruby in Docker, another MCP client such as Claude Desktop, Windsurf or Zed. Each prompt gives every install answer as a flag, so it never stalls on a question. They are in the copy-paste prompts, with prompts to change, upgrade, fix and uninstall the setup.

Uninstall 
bundle exec rails-ai-context uninstall && bundle remove rails-ai-context   # in the Gemfile
rails-ai-context uninstall                                                 # standalone

It removes the context files, the MCP entries, its config, its .gitignore lines and its pre-commit hook, and keeps what you wrote: your lines in CLAUDE.md, other servers in an MCP config, a hook you edited.

Limits

What it will not do

Read this before deciding.

  • No tool writes to your app or your database. Every tool reads. query runs inside a read-only transaction with a timeout, a row limit and column redaction, and refuses anything that is not a read. The assistant still decides what to do with the facts. The six rules in the root file ask it to verify before writing; nothing enforces that.
  • Without a boot, it says less. {{staticIntrospectors}} of {{introspectors}} introspectors answer from the source; the rest say [UNAVAILABLE]. An association a gem adds at boot is not listed, and routes that engines draw are not counted.
  • Rails 9 is not supported. The gemspec caps railties below 9.0, and the standalone binary warns when it boots one.
  • On Windows the MCP configs start the server through cmd /c, and query on SQLite runs without its time limit, since there is no fork.

Questions

Questions you should ask first

Does it send my code anywhere?

No. The tools run on your machine, in your app's process or in a child of it. Two things go online: search_docs fetches Rails guides from GitHub when called with fetch: true, and the standalone binary asks rubygems.org for the latest version at most once a day, sending nothing about the app. RAILS_AI_CONTEXT_NO_UPDATE_CHECK=1 turns that off.

Can it read my secrets?

Files that hold them are never served: .env, config/master.key, credentials.yml.enc, config/database.yml, keys and certificates, and more, on a list you can extend. Logs are redacted before they leave the process, get_config shows credential key names without values, and query never returns an encrypted column.

What if my app cannot boot?

The tools answer from config/routes.rb, the schema dump and the source files, every answer says so, and sections that need a running app say [UNAVAILABLE] with the reason. --no-boot asks for that tier outright. The answers on this page were all recorded that way.

What does it write into my repository?

The MCP config for each AI tool you picked, one root context file with a copy for Copilot, rules files per tool, its own config and two .gitignore lines. A re-run keeps your lines and adds what is missing; uninstall takes back only what it wrote. A team that wants no AI files in the repo can skip the install: the tools work with none of it.

Which AI tools?

Claude Code, Cursor, GitHub Copilot, OpenCode and Codex CLI get context files and MCP config written for them. Any other MCP client, such as Claude Desktop, Windsurf, Zed or a JetBrains IDE, gets an entry from rails-ai-context mcp-entry. A tool with no MCP at all gets the CLI setup, where the context files name the shell commands.

What does it cost?

It is free and MIT licensed. What you pay is tokens, and only when the assistant asks: a tool answer is sized by its detail level and cut at max_tool_response_chars, 200,000 characters by default. The root context file is held to 12,000 bytes in its default compact mode. The line that offers to file an issue costs about 40 tokens an answer and can be turned off.
